## 场景 A: 干净 Windows 环境（首次安装）

### 环境要求
- Windows 10/11
- 无 Claude Code
- 无 Node.js/npm
- 可访问 DeepSeek API
- 可访问 Claude Native Install 通道（或至少可走 fallback）

### 验收步骤

- [ ] 1. 双击 `00-点我开始安装.cmd`
- [ ] 2. 默认选择 `[1]` 一键安装
- [ ] 3. 粘贴 DeepSeek API Key
- [ ] 4. Native Install 优先执行
- [ ] 5. 安装后 User PATH 包含 `%USERPROFILE%\.local\bin`
- [ ] 6. Node.js/npm 未安装时显示 `[INFO]`（不是 ERROR），归入"可选增强项"
- [ ] 7. 完成页建议选择 `[1]` 启动测试（绿色推荐）
- [ ] 8. `[1]` 自动新开终端进入测试项目并运行 `claude`
- [ ] 9. `[2]` 只打开文件夹，不启动 claude
- [ ] 10. `[4]` 生成 report.txt
- [ ] 11. 安装报告包含售后安全提示（只发送 report.txt）
- [ ] 12. 终端输出降噪：Step 2 策略 1 行、Step 5 测试描述 1 行、可选增强项汇总

### 环境要求
- 已安装 Claude Code（Native Install 或 npm）
- 新 PowerShell 可运行 `claude --version`
- 未配置或待更新 DeepSeek API

### 验收步骤

- [ ] 1. 工具检测到已安装 Claude Code
- [ ] 2. 不强制重装
- [ ] 3. 继续配置 DeepSeek API
- [ ] 4. API 测试通过
- [ ] 5. 完成页为"安装流程已完成"
- [ ] 6. `[1]` 可启动测试终端

## 场景 C: Claude 文件存在但 PATH / fresh shell 异常

### 环境要求
- native exe 存在（`%USERPROFILE%\.local\bin\claude.exe`）
- User PATH 缺失或 fresh shell 自动验证失败

### 验收步骤

- [ ] 1. 如果 PATH 缺失，工具尝试修复 User PATH
- [ ] 2. 如果 PATH 已配置但 fresh shell 自动验证失败，完成页显示"安装和配置已完成，建议启动测试确认"
- [ ] 3. doctor 状态为"基本可用"或"建议手动验证"，不是直接失败
- [ ] 4. report 中 Fresh PowerShell 为 WARN，不是 ERROR
- [ ] 5. 下一步建议新开 PowerShell `claude --version` 或选择 `[1]` 测试
- [ ] 6. Node.js/npm 缺失不作为核心错误
