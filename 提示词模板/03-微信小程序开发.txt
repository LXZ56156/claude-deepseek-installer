使用方法：进入小程序项目文件夹运行 claude，复制本模板全文，并描述目标用户和主要功能。
============================================================

请按以下四个阶段工作。

阶段 A：只读检查
查看当前目录、app.json、project.config.json、miniprogram/、已有页面、依赖声明和版本信息，
区分新项目和已有项目。确认目标用户、主要功能、页面和数据来源。
不要默认 Node.js、npm 或微信开发者工具已经安装。

阶段 B：形成判断和计划
说明当前项目判断、发现的问题、最小可运行方案、页面范围和数据流。分析或报告任务无需修改时，
明确写“本阶段无需修改文件”，不要虚构修改项；无需命令时写“无需执行命令”，不要虚构命令。
确实需要变更时才列出准备修改的文件和准备执行的写入命令，并说明风险和影响、验收方法；
安装依赖时单独列出安装计划，不要伪装成代码修改。先做最小版本，不一次创建大量页面。
明确微信开发者工具是预览、真机调试和上传所需工具，Claude Code 不能替代它。

阶段 C：等待用户确认
先给确认项，不要直接给第一个页面代码。安装软件或依赖，创建、修改或删除文件，修改配置或
环境变量，发布上传、调用可能产生费用的 API 和破坏性命令，都必须等我确认。

阶段 D：执行和验收
确认后只创建已确认的最小范围，逐步检查结果，运行可用的测试或静态检查，并说明还需要在
微信开发者工具中完成的预览、真机调试和上传验证。不能完成的验证必须如实报告实际情况。

安全规则：AppID 是项目标识，不等同于 AppSecret；可以在本地分析中确认 AppID 是否存在，
但对外报告或截图应脱敏。不得输出或写入仓库 AppSecret、云开发密钥、API Key、私钥和生产凭据；
不编造文件、命令、功能或验证结果；不改无关文件，不覆盖已有修改；
不执行未经确认的删除、重置或清理；失败时保留原始错误。
未经必要性判断和我确认，不主动读取或输出 .env、settings.json、credentials、私钥文件、Cookie、
密码文件、生产环境配置或客户隐私数据。必须检查时先说明原因并等待确认，优先只看字段名称、结构或
脱敏值；不输出完整秘密，不写入日志、README、测试夹具或仓库，也不要让我粘贴完整敏感文件。
