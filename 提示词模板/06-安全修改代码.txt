使用方法：进入需要修改的项目文件夹运行 claude，复制本模板全文，并描述一个明确问题。
============================================================

请按以下四个阶段工作。

阶段 A：只读检查
先阅读相关代码、配置和测试，尽量复现问题。先运行 git --version，判断当前目录是否为 Git 仓库；
如果是，只读运行 git status。识别并保护用户已有修改，不回退不属于本任务的改动。
无法复现时先请求必要信息或建立最小复现，不盲目修改。

Git 未安装不影响 Claude Code 基础启动，但会影响版本管理、查看改动和安全回退，是强烈推荐的
开发工具。安装前必须询问，不自动安装或配置 Git。

阶段 B：形成判断和计划
说明根因、修改范围和影响，一次只解决一个明确问题，不做无关重构、不升级大量依赖、不删除功能。
如果当前目标只是复现、分析或解释，明确写“本阶段无需修改文件”，不要虚构修改项；
无需命令时写“无需执行命令”，不要虚构命令。确实需要变更时才列出准备修改的文件和准备执行的
写入命令，并说明风险和影响、回退思路和验收方法；安装依赖时单独列出安装计划，不伪装成代码修改。

阶段 C：等待用户确认
安装软件或依赖，创建、修改或删除文件，修改配置或环境变量，git init、commit、push、发布、
付费 API 和破坏性命令都必须等我确认。不要设置 user.name 或 user.email，
不要执行 git reset --hard、git clean 或强制推送。

阶段 D：执行和验收
确认后只做已确认范围，逐步检查结果，运行针对性测试和必要的回归测试。
最终报告根因、修改文件、实际测试、成功与失败、未解决问题和剩余风险，不自动 commit 或 push。

安全规则：不泄露 API Key、密码、Cookie、私钥或完整敏感配置；不编造内容；不改无关文件；
不覆盖已有修改，不执行未经确认的删除、重置或清理；失败时保留原始错误，不用推测代替验证。
未经必要性判断和我确认，不主动读取或输出 .env、credentials、私钥文件、Cookie、密码文件、
生产环境配置或客户隐私数据。%USERPROFILE%\.claude\settings.json 默认敏感，禁止完整读取或输出。
其他 settings.json 先判断用途；普通编辑器设置可以只读检查，可能含凭据时先说明原因并等待确认，
优先只看字段名称、结构或脱敏值。秘密值不写入日志、README、测试夹具或仓库，也不要求我粘贴完整文件。
