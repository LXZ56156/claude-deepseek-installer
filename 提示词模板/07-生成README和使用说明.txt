使用方法：进入项目文件夹运行 claude，复制本模板全文，并说明目标文档、读者和用途。
============================================================

请按以下四个阶段工作。

阶段 A：只读检查
先确认目标文档名称、读者和用途。目标文档可以是 README.md、安装说明、使用说明、配置说明、
常见问题或用户明确指定的其他文档。
读取项目结构、README、依赖声明、真实配置和代码，互相验证。检查文档涉及的路径和文件名是否存在，
确认安装、启动、构建和测试命令来自项目实际配置，并区分必需环境与可选环境。

阶段 B：形成判断和计划
先给目标文档大纲、已确认事实和缺失信息。大纲或分析阶段明确写“本阶段无需修改文件”，
不要虚构修改项；无需命令时写“无需执行命令”，不要虚构命令。
用户确实要求创建或修改目标文档时，才列出该文档和准备执行的写入命令，并说明风险和影响、
验收方法；需要安装依赖时单独列出安装计划，不伪装成文档修改。无法验证的内容标注“需要人工确认”。

阶段 C：等待用户确认
用户确认大纲后才创建或修改目标文档。只要求 README 时就只修改 README；要求独立使用说明时，
不要强制写入 README，也不要修改用户没有指定的其他文档。安装软件或依赖，修改配置或环境变量，
发布、调用可能产生费用的 API 和破坏性命令，都必须另行说明并等待确认。

阶段 D：执行和验收
确认后只做已确认的文档范围，重新检查所有引用和命令。报告哪些内容已由项目实际配置验证、
哪些需要人工确认，以及实际成功、失败和未解决问题。不要编造功能、兼容性或测试结果。

安全规则：不泄露 API Key、密码、Cookie、私钥或真实敏感配置，示例使用明确占位符；
不编造文件、命令或功能；不修改无关文件，不覆盖已有修改；不执行未经确认的删除、重置或清理；
失败时保留原始错误，最终只报告实际执行和实际验证结果。
未经必要性判断和我确认，不主动读取或输出 .env、settings.json、credentials、私钥文件、Cookie、
密码文件、生产环境配置或客户隐私数据。必须检查时先说明原因并等待确认，优先只看字段名称、结构或
脱敏值；不输出完整秘密，不写入日志、README、测试夹具或仓库，也不要让我粘贴完整敏感文件。
