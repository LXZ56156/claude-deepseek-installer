使用方法：进入要检查的项目文件夹运行 claude，复制本模板全文，并补充你的目标。
============================================================

请按以下四个阶段工作。

阶段 A：只读检查
直接查看当前目录、主要文件、README、依赖声明和版本信息，判断我是否位于正确项目目录、
项目技术栈以及真正相关的环境。不要无差别检查或推荐所有语言。
先运行 git --version，判断当前目录是否为 Git 仓库；如果是，只读运行 git status。
发现已有修改时明确提示并保护，不要覆盖或回退。

Git 未安装不影响 Claude Code 基础启动，但会影响项目克隆、版本管理、查看改动和安全回退，
因此它是强烈推荐的开发工具。安装前必须询问我，不要自动安装或配置 Git。

阶段 B：形成判断和计划
先输出项目体检报告：当前目录判断、主要文件、技术栈、必需与推荐环境、发现的问题。
如果当前目标只是检查、分析、解释或生成报告，明确写“本阶段无需修改文件”，不要虚构修改项，
也不要进入文件修改阶段；没有命令需要执行时，明确写“无需执行命令”，不要虚构命令。
只有任务确实需要变更时，才列出准备修改的文件和准备执行的写入命令，并说明风险和影响、验收方法。
需要安装依赖时单独列出安装计划，不要伪装成代码修改。
推荐下一步任务类型，例如继续理解项目、补装环境、开发微信小程序或网页、编写 Python 脚本、
安全修改代码或生成使用说明。不要猜模板编号或文件名；提示我回到 03-常用提示词模板.txt 按任务类型选择。

阶段 C：等待用户确认
此阶段不要修改代码或安装环境。安装软件或依赖，创建、修改或删除文件，修改配置或环境变量，
git init、commit、push、发布，调用可能产生费用的 API，以及破坏性命令都必须等我确认。
不要设置 user.name 或 user.email，不要执行 git reset --hard、git clean 或强制推送。

阶段 D：执行和验收
确认后只做已确认范围，逐步检查结果并运行适合项目的测试。报告实际成功、失败和未解决问题，
不要用“应该可以”代替验证。

安全规则：不泄露 API Key、密码、Cookie、私钥或完整敏感配置；不编造文件、命令或功能；
不顺手修改无关文件，不覆盖已有修改，不执行未经确认的删除、重置或清理；命令保持可审查；
失败时保留原始错误，最终只报告实际执行和实际验证结果。
未经必要性判断和我确认，不主动读取或输出 .env、credentials、私钥文件、Cookie、密码文件、
生产环境配置或客户隐私数据。%USERPROFILE%\.claude\settings.json 默认敏感，禁止完整读取或输出。
其他 settings.json 先判断用途；普通编辑器设置可以只读检查，可能含凭据时先说明原因并等待确认，
优先只看字段名称、结构或脱敏值。秘密值不写入日志、README、测试夹具或仓库，也不要求我粘贴完整文件。
